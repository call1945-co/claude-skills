# 주석 검사

이 검사가 보는 것은 하나다: **주석이 짧고, 사람이 쓴 한국어이고, 코드에 없는 이유만 말하는가.** 결과는 언제나 "지울 주석"과 "줄인 문장"의 목록이다. 주석을 늘리는 권고는 이 검사의 결과물이 아니다.

## 절차

1. **기계 검사** — 저장소(또는 worktree) 폴더에서 돌린다.
   ```
   python ~/.claude/skills/comment-check/scripts/check_comments.py <파일·폴더 ...>
   python ~/.claude/skills/comment-check/scripts/check_comments.py --diff origin/develop   # MR 전: 바뀐 줄의 주석만
   ```
   걸리는 사유: `LEN`(한 줄 50자 초과) · `LINES`(설명 4줄 이상, 파일 헤더는 6줄 이상) · `STACK`(`—`·`( )` 겹침) · `HIST`(MR 번호·날짜·누가 정했는지) · `TONE`(번역투).
2. **판단 검사** — 대상 파일의 주석을 **모두** 읽고(스크립트가 안 걸었어도) 주석마다 묻는다: *"이 주석을 지우면 읽는 사람이 무엇을 잃나?"*
   - 코드·함수 이름·변수 이름을 읽으면 아는 내용 → **삭제**
   - 이유·함정·바깥 제약(다른 파일 값과 맞춰야 함, 브라우저·IME 동작, 외부 시스템 규칙) → **한 줄로 줄임**
   - 동작 설명과 이유가 섞여 있으면 → 동작 설명은 지우고 **이유만 한 줄로 남긴다** (예: "아래 자리가 모자라면 위로" 를 지워도 "모달 안에서 잘리지 않게" 는 남긴다)
   - 읽다가 코드와 다른 주석을 보면 → 사유를 `[틀림]` 으로 적고 맞는 문장으로 고친다
3. 걸린 주석마다 고친 문장을 쓴다(아래 형식).

## 결과 형식

이 모양 그대로 돌려준다. 주석 하나에 한 줄.

```
파일:줄 [사유] → 고친 주석
파일:줄 [사유] → 삭제
...
주석 N개 / 고칠 것 M개 (삭제 a, 줄임 b)
```

파일은 사용자가 "고쳐줘"라고 할 때 바꾼다. 고친 뒤 스크립트를 다시 돌려 0건인지 확인한다.

## 고치는 법

| 사유 | 처방 |
|:--|:--|
| 코드를 다시 설명 | 삭제 |
| LEN·LINES | 이유 하나만 남긴다. 나머지 동작 설명은 삭제, 결정 배경은 MR 본문으로 |
| STACK | 괄호·대시 뒤 보충은 대부분 삭제. 진짜 함정이면 그것만 한 줄 |
| HIST | 주석에서 지운다(커밋·MR 본문에 있다) |
| TONE | "~에 대해 조회" → "~를 조회", "~에 의해 입력된" → "~가 입력한", "~을 위해" → "~려고/~도록", "되어진" → "된", "수행한다/제공한다" → 구체 동사 |
| JSDoc `@param` | 이름·타입으로 드러나면 설명을 지운다. 설명이 없는 `@param` 은 정상이다 |

## 예

| 지금 | 고친 것 |
|:--|:--|
| `칠 때마다 — 입력이 잠깐 멈추면 찾는다 (한글 조합 중 input 도 받는다 — v-model 은 글자가 완성돼야 바뀐다)` | `한글 조합 중에도 찾으려고 v-model 대신 input 을 쓴다` |
| `팝업 위치 계산용 — Dropdown.scss 의 목록 폭, 최대 높이(320)와 그 위 검색 줄 높이` | `.scss 의 폭·높이와 값을 맞춰야 한다` |
| `검색 — 검색어가 있으면 필터 화면(일치 항목과 그 상위만), 없으면 트리 화면` | 삭제 (아래 computed 가 그대로 말한다) |
| `팀장 결정(2025-03-02, MR !42)으로 필터 방식` | 삭제 |

## 스크립트 결과를 버리는 경우

- 파일 헤더의 `@author`·`@since`·`@modified` 줄 — 형식 규칙이라 그대로 둔다. 헤더 **설명 문장**은 검사한다.
- 타입 모양·정규식·URL·코드 예시를 담은 주석(`노드: { id, parentId, ... }`)의 `LEN`.
- 사람 이름이 아닌 `결정`(예: "정렬 순서를 결정한다").

## 흔한 실수

- 주석이 코드와 맞는지, 헤더가 있는지, 설명이 빠졌는지를 보고 "위반 0건"으로 끝낸다 → 그건 다른 리뷰다. 이 검사는 길이·문체·필요성만 본다.
- "매개변수 설명을 추가하라"고 권고한다 → 이 검사의 방향과 반대다.
- 스크립트 결과만 옮겨 적는다 → 2단계 판단 검사(삭제할 주석 찾기)가 빠진다.
