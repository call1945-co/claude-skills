# ISMS-P 컴플라이언스 구현

ISMS-P 인증 기준과 개인정보 안전성 확보조치 기준을 코드로 지키는 규약이다. 헥사고날 구조(`hexagonal-architecture`)를 전제로 하지만, 원칙은 구조와 상관없이 같다.

## 0. 프로젝트 값

처음 쓸 때 `CLAUDE.md`·기존 코드에서 찾는다. **이미 있는 포트·어노테이션·마스킹 유틸이 있으면 새로 만들지 않고 그것을 쓴다.**

| 항목 | 예 |
|:--|:--|
| 암호화 포트 → 구현 | `PiiCryptoPort` → `AwsEncryptionSdkAdapter` |
| 비밀번호 해시 포트 | `PswdHashPort` |
| 접속기록 | `@PiiAudit` + Aspect → `AuditLogPort` → 감사 테이블 |
| 마스킹 | `PiiMask` |
| 현재 사용자·범위 | `CurrentUserPort.requireUser()` → `AuthPrincipal.toDataScopeCond()` |
| 테넌트 키 | `CLNT_NO`, `TENANT_ID` |
| 컬럼 접미사 | 암호문 `_ENC`, 검색 해시 `_HASH` |

## 1. 개인정보 암호화

### 1-1. 포트

```java
String encrypt(String plain, Map<String, String> context);   // 봉투암호화 → Base64
String decrypt(String cipher, Map<String, String> context);  // context 가 다르면 실패
String generateSearchHash(String plain);                     // HMAC-SHA256, 소문자 hex 64자
```

- **어댑터 경계(영속 어댑터·Mapper)에서만** 암·복호화한다. Service·Controller·도메인은 평문만 다룬다. JPA Converter·유틸 클래스·KMS 클라이언트를 따로 만들지 않는다.
- 조회 조건(주민번호로 찾기)은 `generateSearchHash()` 결과로 `*_HASH` 컬럼을 조회한다. 복호화한 뒤 비교(전수 스캔)하지 않는다.
- **Encryption Context** 에는 치환 공격을 막는 식별자 `{tbl, col, tenant}` 를 넣는다. IDENTITY PK 는 INSERT 전에는 없으니 넣지 않는다.
- **context 에 검색 해시를 넣지 않는다.** SDK 는 context 를 암호문 헤더에 평문으로 저장한다. 해시가 암호문에 남고, 해시 키를 바꿀 때마다 재암호화가 따라온다.

### 1-2. AWS Encryption SDK + KMS 를 쓸 때

- 마스터 키 공급자는 `com.amazonaws.encryptionsdk.kmssdkv2.KmsMasterKeyProvider`(AWS SDK v2)만 쓴다. 같은 이름의 `encryptionsdk.kms` 는 SDK v1 용이다. Encryption SDK 가 v1 을 선택 의존성으로만 선언해서 bootJar 에 없고, 첫 암·복호화 때 `NoClassDefFoundError` 가 난다. Error 라서 `catch (RuntimeException)` 에도 걸리지 않는다.
- 공급자는 생성자에서 한 번 만든다. 설정에는 **키 ARN**(`key/…`)을 넣는다. 별칭(alias) ARN 으로 만든 strict 공급자는 암호화만 되고 복호화가 모두 실패하므로, 기동 때 막는다.
- `CommitmentPolicy.RequireEncryptRequireDecrypt` 를 쓴다.
- **AWS 자격증명이 없는 로컬·개발 환경**은 같은 어댑터에서 공급자만 `JceMasterKey`(AES-256/GCM, 로컬 마스터 키)로 바꾼다. 알고리즘·정책·context·암호문 형식은 그대로 둔다.
  - 키 ARN 과 로컬 키가 둘 다 있으면 기동을 실패시킨다.
  - 운영·STG 는 `kms-required=true` 로 두어 키 ARN 이 없거나 로컬 키가 들어오면 기동을 실패시킨다. 이 설정을 지키는 테스트를 둔다.
  - 기동 로그에 키 확인값(키 해시 앞 몇 자리)을 남긴다. 같은 DB 를 쓰는 인스턴스끼리 값이 같아야 한다.
  - 로컬 암호문은 운영에서 풀리지 않는다. 로컬 키를 바꾸면 기존 개발 데이터는 다시 만든다.

### 1-3. 검색 해시

- **HMAC-SHA256** 을 쓴다. 키 없는 SHA-256 은 휴대폰(약 1억 경우)이나 주민번호(생년월일·성별이 같은 행에 있으면 경우의 수가 작다)를 전수 대입으로 되돌릴 수 있다. `MessageDigest` 를 직접 쓰지 않는다.
- 해시 키는 DB 밖에 둔다. 운영에서는 KMS 로 감싼 값을 환경변수로 받아 기동 때 한 번 풀고 메모리에만 둔다. 평문 키가 들어오면 기동을 실패시킨다.
- 키가 없으면 해시 생성이 예외를 던지게 한다. 임시 난수 키로 대신하면 재기동할 때마다 해시가 달라져 검색이 깨진다.
- 해시 입력은 정규화한 값(숫자만)이다. 저장 경로와 재계산 Job 이 같은 정규화를 써야 한다.
- 키를 바꾸면 재계산 배치로 모든 `*_HASH` 를 다시 만든다. 배치는 기본 dry-run 으로 돌리고 실행자를 접속기록에 남긴다. 수정일을 보존하고(`mdftDate = mdftDate`), 읽은 암호문과 비교한 뒤 갱신한다.
- **짝이 되는 `*_ENC` 가 없는 해시 전용 컬럼(DI 등)은 재계산할 수 없다.** 키를 바꾸면 비우거나 다시 수집해야 한다. 새 해시 컬럼을 만들 때 재계산 대상에 넣는다.
- 기동 로그의 해시 키 확인값은 API·배치 인스턴스가 모두 같아야 한다. 키가 달라도 오류 없이 기동하고 해시만 어긋난다.

### 1-4. 컬럼 규약

| 데이터 | 암호문 | 검색 해시 | 비고 |
|:--|:--|:--|:--|
| 주민·외국인등록번호 | `*_ENC` | `*_HASH` | 인덱스 `(테넌트, *_HASH)`, 조회는 해시로만 |
| 휴대폰 | `*_ENC` | `*_HASH` | 발송 직전에만 복호화 |
| 계좌번호 | `*_ENC` | 필요 시 | 은행 코드는 평문 |
| 비밀번호 | 단방향 해시 | — | 3절 |
| DI | — | `DI_HASH` | 원문 저장 금지. CI 는 꼭 필요하지 않으면 저장하지 않는다 |

- `*_ENC` 는 **VARCHAR(2000)** 으로 잡는다. 봉투암호문은 서명·context·감싼 데이터 키를 머리에 담아 Base64 로 약 1KB 가 된다. context 값이 길수록 길어진다. 엔티티 컬럼 길이에 들어가는지 테스트로 지킨다.
- 새 개인정보 컬럼은 `_ENC`(+검색이 필요하면 `_HASH`) 쌍으로 만들고, 스키마 기준 파일에 반영한다.

### 1-5. 마스킹

- 로그·예외 메시지·`toString()` 에 평문 개인정보를 남기지 않는다. 마스킹 예: 주민번호 `901231-1******`, 휴대폰 `010-****-5678`, 계좌는 뒤 4자리만 남긴다.
- 외부 시스템 응답·오류 문장을 이력에 남길 때는 문장 안의 값을 가린다(주민·외국인번호, 휴대폰, 10자리 이상 숫자).
- API 응답은 기본으로 마스킹 값을 준다. 원문은 별도 엔드포인트로만 주고 접속기록을 남긴다. 프론트는 서버가 준 값을 그대로 표시하고 원문을 조합하지 않는다.

## 2. 개인정보 접속기록

- **대상**: 개인정보가 담긴 목록 조회, 단건 상세(원문) 조회, 엑셀·CSV·파일 다운로드, 수정·삭제, 복호화 호출.
- **항목**: 접속자, 일시, IP, 수행 업무(VIEW/DETAIL/DOWNLOAD/UPDATE/DELETE), 조회 조건, 대상(다건이면 건수와 조건), **다운로드 사유**(필수), 결과 코드.
- **구현**: 컨트롤러 메서드에 어노테이션(`@PiiAudit(actnType, trgtParam, rsonParam, rsonRequired)`)을 붙이고, Aspect 가 접속자·IP·URI·결과를 채운다. 예외가 나도 기록한다. 서비스 내부 이벤트(승인·반려·서명)는 포트를 직접 부른다.
- 저장은 별도 트랜잭션(`REQUIRES_NEW`)에 INSERT 로만 한다. 수정·삭제 경로를 두지 않는다. 값은 컬럼 길이로 잘라서 넣는다. 길이 초과로 INSERT 가 실패하면 기록이 사라진다.
- 접속기록의 어느 필드에도 평문 개인정보를 넣지 않는다. 주민번호 검색 입력값은 해시나 마스킹 값으로 남긴다.
- **파일을 돌려주는 API 는 "보기"라도 DOWNLOAD 로 남기고 사유를 받는다.** 받은 바이트는 저장할 수 있기 때문이다. 문서 식별(문서 번호·서식 버전·파일 해시)을 남겨 어느 판본을 봤는지 알 수 있게 한다. 실패한 시도도 오류 코드로 남긴다.
- 본인(신청자) 채널처럼 관리자 주체가 없는 경로는 서비스가 직접 기록한다. 대상이 곧 본인이다. 사용자 입력은 형식을 검증한 뒤에만 기록에 넣는다.
- **보관 기간**: 접속기록은 최소 1년이다(5만 명 이상·고유식별정보·민감정보 처리 시스템은 2년). 금융권은 보통 2년 이상이다. **접근권한 부여·변경·말소 이력은 최소 3년**이다(안전성 확보조치 기준 제5조). 파기 배치는 업무 유형별 기간을 따른다.
- 접근권한 변경 이력은 할당마다 한 행으로 남기고, 같은 요청은 묶음 ID 로 묶는다. 조직·직급으로 권한이 바뀌는 구조면 로그인 기록에 유효한 할당 요약을 남긴다.

## 3. 계정·세션 통제

이미 있는 인증 서비스·토큰 어댑터·보안 설정을 쓰고, 새 인증 로직을 만들지 않는다.

- **비밀번호**: 솔트와 반복을 쓰는 단방향 해시(PBKDF2·bcrypt·SHA-512 반복)로만 저장한다. 평문·양방향은 금지한다. 정책(길이·조합·아이디 포함 금지)은 한 곳에서 판정한다.
- **로그인 실패 잠금**: 5회면 계정을 잠근다. 실패 횟수는 로그인 트랜잭션이 롤백돼도 커밋되게 한다(`noRollbackFor`).
- **비밀번호 만료**: 만료되면 토큰에 변경 필요 표시를 넣고, 필터가 비밀번호 변경·로그아웃·재발급 외의 API 를 막는다.
- **토큰**: 액세스 토큰은 30분 이하로 하고, 리프레시 유휴 TTL 보다 짧게 둔다. 그래야 만료 뒤 재발급이 된다. 리프레시 토큰은 서버 저장소(Redis)에 두고 1회용으로 회전시킨다. 세션 최대 시간을 따로 둔다. 프론트는 만료 코드를 받으면 재발급한 뒤 한 번만 재시도한다.
- 현재 사용자는 포트로 받는다. 배치처럼 웹 요청이 없는 맥락에서는 빈 값이다.

## 4. 데이터 권한 범위 (RBAC)

**모든 목록·상세 조회 쿼리에 범위 조건을 서버에서 강제한다.** 프론트 필터만으로 통제하지 않는다.

| 범위 | 쿼리 조건 |
|:--|:--|
| 전사(본사) | `테넌트 = :tenant` 만 |
| 하위 조직 포함 | `조직경로 LIKE :루트경로 || '%'` |
| 그 조직만 | `조직경로 = :루트경로` |
| 본인 | `담당자 = :userNo` (범위를 하나도 못 받으면 여기로 — fail-closed) |

- 모든 쿼리에 **테넌트 키 조건**이 들어가야 한다.
- 역할을 여러 개 할당할 수 있으면 할당마다 범위를 grant 로 펼쳐 **OR** 로 조회한다. 결재·원문 같은 능력은 그 grant 의 범위 안에서만 쓴다.
- **원문 열람**은 원문 권한이 사용자의 모든 조회 범위를 덮을 때만 준다. 일부만 덮으면 전체를 마스킹한다.
- 토큰 클레임이 빠지면 닫힌 쪽(거부·최소 권한)으로 해석한다.
- 권한을 주는 변경은 토큰이 아니라 DB 의 현재 상태로 다시 판정한다. 요청자 자신의 할당은 바꿀 수 없게 한다.
- 권한은 자체 RBAC 테이블로만 판정하고, 외부·레거시 시스템 권한 테이블과 JOIN 하지 않는다.

## 5. 자격증명

DB 계정·비밀번호, 토큰, API 키, 키 ARN 은 소스·`.md` 문서·yml 에 평문으로 넣지 않는다. 환경변수나 Secrets Manager 를 참조한다. `dev-review` 의 pre_mr_check 가 추가된 줄을 검사한다.

## 6. 작업 전 체크리스트

- [ ] 개인정보 컬럼이 `_ENC`(+`_HASH`)로 설계됐고 스키마 기준 파일에 반영됐는가
- [ ] 암·복호화가 암호화 포트를 거치고 어댑터 경계에서만 일어나는가
- [ ] 검색은 HMAC 해시 컬럼으로 하는가 (복호화 후 비교 없음)
- [ ] 로그·예외·응답에 평문 개인정보가 없는가
- [ ] 개인정보 조회·다운로드 API 에 접속기록이 있는가 (다운로드는 사유 필수)
- [ ] 조회 쿼리에 테넌트 키와 데이터 범위 조건이 들어갔는가
- [ ] 자격증명이 소스·문서에 평문으로 들어가지 않았는가
